# 예측 서비스 기획 회의안 v2

> 컨셉: **"예측 시장을 오락이 아니라 도구로 쓴다"**
> 두 축 — ① 팀의 일정에 베팅하는 **스프린트 예측 시장** ② 내 목표에 남들이 베팅하는 **셀프 커밋먼트 마켓**
> 같은 컨트랙트(Sub PJT 명세 구조 그대로)에 이벤트 카테고리만 두 개. 구현 리스크는 스포츠 예측과 동일, 서사만 뒤집힘.

---

## 1. 한 줄 피치

> **"말 못 하는 일정 리스크는 배당률이 말하게 하고, 지키기 힘든 목표는 남의 베팅이 지키게 한다."**

- 포지셔닝: 도박 X → **집단지성 forecasting + 동기부여 장치**. 구글·HP의 사내 예측 시장(internal prediction markets) 선례 인용 가능.
- 교육용 ERC-20 토큰 사용 명시 (현금 가치 없음).

## 2. 두 카테고리

### A. 스프린트 예측 시장 (팀/조직용)
- 이벤트 예: "이번 스프린트 마감 내 완료?", "기능 X 금요일까지 머지?", "이번 주 CI 첫 시도 통과율 80% 이상?"
- 가치: 회의에서 아무도 말 안 하는 일정 리스크가 **배당률로 조기 노출** → 관리 도구.
- 결과 판정: GitLab/Jira 상태(머지 여부, 이슈 완료, 파이프라인 결과)를 API/웹훅으로 수집 → 관리자 화면에 "제안된 정답 + 근거" 표시 → **관리자가 확인 후 지갑 서명** (명세의 직접 서명 원칙 유지, 반자동 오라클).
- 데모 시나리오: **우리 팀 GitLab 자체를 데모 데이터로** — "우리 프로젝트 일정에 우리가 베팅했다"는 발표 훅.

### B. 셀프 커밋먼트 마켓 (개인용)
- 이벤트 예: "나 이번 주 백준 15문제 푼다", "이번 주 매일 1커밋", "이번 달 CS 스터디 개근"
- 인센티브 구조: 본인이 실패하면 실패에 건 사람들이 배당을 가져감 → **약속을 어기는 게 실제로 아까워짐**. (본인이 '실패'에 걸어 보험처럼 쓰는 것 허용 여부 → 회의 결정사항)
- 결과 판정: solved.ac / GitHub API로 **자동 검증 가능** — 근거가 코드로 증명됨.
- 이벤트 공급: 사용자가 스스로 생성 → 공급 무한, 시즌 의존 없음.

## 3. 오라클 설계 (이 기획의 기술적 차별화 핵심)

1. **근거 수집기(off-chain)**: 외부 API(GitLab, solved.ac, GitHub)에서 결과 후보 + 근거 스냅샷 자동 수집
2. **관리자 확인**: 관리자 화면에 "제안 정답 / 근거 / 수집 시각" 표시 → 관리자 지갑 서명으로 확정 (명세 흐름 그대로)
3. **근거 공시**: resolve 시 근거 URL·스냅샷 해시를 DB+화면에 기록, 확정 tx 해시 검증 UI 제공
→ 면접 스토리: "수동 확정이라는 명세 제약 안에서 오라클을 어떻게 신뢰 가능하게 만들 것인가"를 설계한 경험.

## 4. 엣지 케이스 정책 (회의에서 확정)

- 정답 풀 0 → **환불 모드** (명세 선택과제, 구현 확정 제안)
- 정수 나눗셈 잔여 토큰 → **회수 정책** (명세 선택과제, 구현 확정 제안)
- 이벤트 취소/판정 불가(예: 스프린트 자체가 취소) → 전원 환불 절차
- 셀프 커밋먼트 악용 방지: 본인 참여 허용 범위(본인은 '성공'에만? 금지? 보험 허용?), 목표 난이도 검수 규칙
- 판정 근거 소스가 다운됐을 때 → 확정 보류 + 재시도 규칙

## 5. 범위 (MVP → 확장)

- **MVP (평가 직결)**: 명세 필수 흐름 전체 + 카테고리 2종 + 근거 공시·tx 검증 UI + 환불·잔여토큰 정책
- **2차**: 반자동 오라클(API 수집기), 실시간 배당률 표시, 마이페이지(참여/정산 내역)
- **하지 않는 것**: claim/Merkle 정산, 현금성 요소, 주관 판정 이벤트
