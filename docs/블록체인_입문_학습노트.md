# 블록체인 입문 학습노트 — 예측 서비스 프로젝트 기준

> 대본이 아니라 **원리 설명**. "블록체인이 뭐고, 디앱이 뭐고, 뭘로 짜는지"를
> 우리 프로젝트(Solidity + Hardhat + ethers + MetaMask + SSAFY 체인) 기준으로 정리.
> 불씨제로에서 익힌 개념과 연결되는 지점은 ★로 표시.

---

# 1. 블록체인이 뭔가

## 1-1. 한 문장 정의

> **"서로 믿지 않는 여러 컴퓨터가 똑같은 장부(DB)를 나눠 갖고, 정해진 규칙으로만 추가할 수 있게 만든 시스템."**

일반 DB와의 차이는 세 가지뿐입니다:

| | 일반 DB (MySQL) | 블록체인 |
|---|---|---|
| 누가 관리 | 한 회사/서버 | 여러 노드가 같은 사본을 유지 |
| 수정/삭제 | UPDATE, DELETE 가능 | **추가(append)만 가능**, 과거는 못 고침 |
| 신뢰의 근거 | "운영자를 믿는다" | "수학(해시·서명)과 합의 규칙을 믿는다" |

## 1-2. 왜 과거를 못 고치나 — 해시 체인

- 거래들을 묶은 덩어리가 **블록**. 각 블록은 "이전 블록의 해시값"을 품고 있음.
- 해시는 입력이 1비트만 바뀌어도 완전히 달라지는 지문 → 과거 블록 하나를 고치면
  그 뒤 모든 블록의 해시가 연쇄적으로 어긋남 → 조작이 즉시 들통.
- "블록 + 체인"이라는 이름 자체가 이 구조.

## 1-3. 합의(Consensus) — 누가 다음 블록을 쓰나

여러 노드가 같은 장부를 유지하려면 "다음 블록은 이거다"를 합의해야 함.

- **PoW(작업증명)**: 어려운 계산 퍼즐을 먼저 푼 노드가 씀 (비트코인). 전기 많이 먹음.
- **PoS(지분증명)**: 코인을 맡긴(스테이킹) 노드 중 추첨 (현재 이더리움 메인넷).
- **PoA(권한증명)**: **미리 허가된 노드만** 돌아가며 씀. 기업/교육용 사설망 방식.
  → **SSAFY 체인(Hyperledger Besu 기반)이 이 계열.** 그래서 빠르고, 가스비가 없고(gasless), 참여 노드가 통제됨.

## 1-4. 퍼블릭 vs 프라이빗

- 퍼블릭: 누구나 노드 참여 (이더리움 메인넷, 테스트넷 Sepolia 등)
- 프라이빗/컨소시엄: 허가된 노드만 (Besu, Hyperledger Fabric) — **우리 실습 환경**
- 우리 입장 정리: "퍼블릭 이더리움과 같은 기술(EVM)을 쓰는 사설 체인에서 개발한다.
  코드는 메인넷과 동일하게 동작하고, 돈(가스비)만 안 든다."

# 2. 이더리움 — 스마트 컨트랙트라는 발명

## 2-1. 비트코인과의 차이

비트코인 장부에 적히는 건 "A가 B에게 얼마 보냄"뿐. 이더리움은 장부에 **프로그램(코드)을 올리고,
그 프로그램의 실행 결과까지 모두가 검증**할 수 있게 함. 이 프로그램이 **스마트 컨트랙트**.

> 스마트 컨트랙트 = "블록체인 위에 배포된, 누구도 임의로 못 고치는 서버리스 백엔드 코드"
> 배포하면 코드가 불변이고, 상태(변수 값)는 트랜잭션으로만 바뀜.

## 2-2. 계정(Account) 두 종류 — 헷갈리기 쉬운 핵심

| | EOA (외부 소유 계정) | CA (컨트랙트 계정) |
|---|---|---|
| 정체 | 사람의 지갑 (MetaMask) | 배포된 컨트랙트 |
| 개인키 | **있음** — 서명 가능 | 없음 — 스스로 시작 못 함 |
| 주소 예 | 0xAb3f... (20바이트) | 0x7C9e... (똑같이 생김) |
| 우리 프로젝트 | 관리자·사용자 지갑 | TestToken, Factory, PredictionEvent |

**모든 트랜잭션의 시작점은 반드시 EOA.** 컨트랙트는 호출당해야만 움직인다.
(우리 명세의 "서버가 개인키 대행 금지, 본인 지갑 직접 서명" 원칙이 여기서 나옴 — 개인키를 가진 자 = 그 계정의 주인)

## 2-3. 개인키 → 공개키 → 주소

- **개인키**: 256비트 난수. **이게 곧 계정의 소유권.** 유출 = 계정 탈취, 분실 = 영구 접근 불가.
- 개인키로 **서명**을 만들면, 누구나 공개키로 "이 서명은 진짜 그 사람 것"을 검증 가능 (타원곡선 암호).
- **주소** = 공개키의 해시 뒤 20바이트. MetaMask가 보여주는 0x... 가 이것.
- **니모닉(시드 구문)**: 12/24개 영단어 = 개인키를 사람이 백업 가능하게 인코딩한 것. 절대 공유 금지.

## 2-4. 트랜잭션(tx) — 상태를 바꾸는 유일한 방법

트랜잭션 = "서명된 상태 변경 요청". 구성: 보내는 주소(서명으로 증명) / 받는 주소 / 데이터(어떤 함수를 어떤 인자로) / nonce / 가스.

흐름: **서명 → 노드에 제출 → 대기풀(mempool) → 블록에 포함 → 각 노드가 실행·검증 → 영수증(receipt) 발급**

- **nonce**: 계정별 트랜잭션 일련번호. 재사용 불가 → **재전송 공격 방지 + 순서 보장** ★(MQTT 명령 멱등 처리와 같은 문제의식)
- **영수증(receipt)**: status(성공/실패), 어느 블록에 포함됐는지, **이벤트 로그** 포함.
  → 우리 백엔드가 하는 일의 절반이 "영수증 검증"인 이유: **화면의 성공 메시지가 아니라 영수증이 진실**.
- **조회(call)는 트랜잭션이 아님**: view 함수 읽기는 서명·수수료·블록 포함이 전부 불필요, 그냥 노드에 물어보면 끝.
  → **쓰기는 비싸고 느리다(블록 대기), 읽기는 공짜다** — 온체인/오프체인 설계의 대전제.

## 2-5. 가스(gas)

- 연산 1스텝마다 매기는 수수료 단위. 무한루프 코드로 네트워크를 마비시키는 걸 막는 장치.
- 퍼블릭에선 ETH로 지불. **SSAFY 체인은 gasless라 0원** — 하지만 가스 "한도"는 존재해서
  반복문이 너무 길면 실패함 (Sub PJT 3에서 참여자 루프 정산의 한계 → claim 방식이 언급되는 이유).

## 2-6. EVM

이더리움 가상 머신. 모든 노드에 들어 있는 동일한 실행기. Solidity 코드는 EVM **바이트코드**로 컴파일되어 배포됨.
"EVM 호환 체인"(Besu, Polygon 등)이란 이 실행기를 똑같이 쓰는 체인 → **코드 재사용 가능. SSAFY 체인도 EVM 호환.**

# 3. 디앱(dApp) — 구조가 일반 웹앱과 뭐가 다른가

## 3-1. 정의

dApp(Decentralized App) = **핵심 로직/상태의 일부를 스마트 컨트랙트에 둔 웹 애플리케이션.**
전부 탈중앙일 필요 없음 — 실전 디앱은 대부분 하이브리드(우리도 마찬가지).

## 3-2. 구조 비교 ★불씨제로와 비교하면 바로 이해됨

```
[일반 웹앱 - 불씨제로]
브라우저(Vue) ──REST/SSE──> 서버(Spring) ──JPA──> MySQL
                             └─ 서버가 모든 진실의 원본

[디앱 - 예측 서비스]
브라우저(React) ─┬─ ethers ──> MetaMask(서명) ──> RPC 노드 ──> 컨트랙트   ← 돈·규칙 (진실의 원본)
                 └─ REST ───> 백엔드(Express) ──> PostgreSQL              ← 제목·이미지·검색 (조회용 사본)
```

핵심 차이 두 가지:
1. **브라우저가 서버를 거치지 않고 직접 블록체인에 쓴다** (지갑 서명). 서버는 그 결과를 "검증하고 따라 적는" 입장.
2. **인증의 주체가 다르다.** 웹앱은 서버가 세션/JWT 발급 ★(auth_design_memo에서 설계했던 것).
   디앱의 자산 조작은 **지갑 서명 자체가 인증** — 서버가 뚫려도 사용자 돈은 못 건드림. 이게 구조의 존재 이유.

## 3-3. 왜 백엔드/DB가 여전히 필요한가 (면접 단골)

- 온체인 저장은 비싸고(모든 노드에 복제), 검색·정렬·집계가 안 됨 (WHERE, LIKE, JOIN 없음)
- 이미지·긴 텍스트를 올릴 곳이 아님 → 제목/설명/이미지는 DB, 돈/규칙/결과는 체인
- **원칙: 온체인이 원본(source of truth), DB는 빠른 조회용 사본.** 어긋나면 온체인 로그 기준으로 DB를 복구.
  ★불씨제로의 "명령 상태의 원본은 서버 DB, 화면은 사본" 관계와 동형 — 원본의 위치만 바뀜.

# 4. 뭘로 짜나 — 언어와 도구 체인

## 4-1. 전체 지도

| 층 | 도구 | 역할 | 비유 (Spring 스택 기준★) |
|---|---|---|---|
| 컨트랙트 언어 | **Solidity 0.8.24** | 온체인 로직 작성 | Java |
| 컨트랙트 라이브러리 | **OpenZeppelin 5.x** | 검증된 표준 구현(ERC20, Ownable) | Spring Boot starter |
| 개발 프레임워크 | **Hardhat 3** | 컴파일·로컬체인·테스트·배포 | Gradle + 로컬 Tomcat + JUnit |
| 체인 통신 라이브러리 | **ethers.js 6** | JS에서 노드/컨트랙트 호출 | JPA/RestTemplate (체인용 드라이버) |
| 지갑 | **MetaMask** | 개인키 보관 + 서명 UI | (대응물 없음 — 사용자가 든 인증서) |
| 노드/네트워크 | SSAFY 체인 (Besu, chainId 31221) | 트랜잭션 실행·저장 | DB 서버 + WAS를 합친 것 |
| 오프체인 | React·Express·PostgreSQL | 화면·조회 API·사본 저장 | 기존 웹 스택 그대로 |

## 4-2. Solidity 최소 문법 — 우리 컨트랙트에 나오는 것만

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;                    // 컴파일러 버전 고정

contract PredictionEvent {
    // ── 상태 변수: 블록체인에 영구 저장됨 (= DB 컬럼. 쓰기마다 가스)
    address public owner;                    // 20바이트 주소 타입
    bool public resolved;
    uint256 public totalBetAmount;           // 부호 없는 256비트 정수 (기본 정수형)
    string[] public options;                 // 동적 배열

    mapping(address => Bet) private bets;    // 해시맵. ⚠ key 목록 순회 불가 → 필요하면 별도 배열 유지
    struct Bet { uint256 optionId; uint256 amount; bool participated; }

    // ── 이벤트: "로그를 남긴다" 선언. 상태가 아니라 영수증에 기록됨 (아래 4-3)
    event BetPlaced(address indexed user, uint256 indexed optionId, uint256 amount);

    // ── modifier: 함수 앞에 붙는 공통 검사 (= Spring 인터셉터/AOP ★)
    modifier onlyOwner() { require(msg.sender == owner, "not owner"); _; }

    // ── 함수
    function placeBet(uint256 optionId, uint256 amount) external {
        // msg.sender = 이 tx에 서명한 사람의 주소. 위조 불가능한 "인증된 요청자"
        if (resolved) revert EventResolved();        // custom error — require보다 가스 싸고 명확
        require(amount > 0, "zero amount");          // 실패 시 전체 롤백

        bets[msg.sender] = Bet(optionId, amount, true);   // 상태 변경 먼저
        totalBetAmount += amount;
        token.safeTransferFrom(msg.sender, address(this), amount);  // 외부 호출은 마지막
        emit BetPlaced(msg.sender, optionId, amount);
    }
    error EventResolved();
}
```

외워둘 규칙들:
- **revert = 전체 롤백.** 컨트랙트 함수 하나 = DB 트랜잭션 하나 ★(@Transactional이 언어에 내장된 셈). 중간 실패 시 모든 상태 변경이 취소됨.
- **view 함수**(읽기 전용)는 가스 0, 서명 불필요. 쓰기 함수와 명확히 구분할 것.
- **Checks-Effects-Interactions**: 검증 → 내 상태 변경 → 외부 호출(토큰 전송) 순서.
  외부 호출이 나를 되호출하는 **재진입(reentrancy) 공격**의 방어 기본기 (The DAO 해킹 사건의 교훈).
- 소수점 없음! 전부 정수 연산 → 나눗셈은 버림 → **곱셈 먼저, 나눗셈 나중에** (정산 공식에서 중요).
- block.timestamp = 현재 블록 시각(초). openTime/closeTime 비교에 사용.
- 컴파일 결과물 = **바이트코드**(체인에 올라가는 것) + **ABI**(함수 목록 명세 JSON — 외부에서 호출할 때 쓰는 "API 문서" ★swagger 스펙 같은 것).

## 4-3. 이벤트 로그 — 디앱 아키텍처의 숨은 주인공

`emit BetPlaced(...)`는 상태 저장이 아니라 **영수증에 로그를 남기는 것.**
- 컨트랙트 안에서는 다시 못 읽음. 대신 **밖(백엔드)에서 조회·구독 가능**하고 저장 비용이 상태 변수보다 훨씬 쌈.
- `indexed` 붙은 파라미터(최대 3개)는 검색 필터로 사용 가능.
- **우리 백엔드 로직의 근간**: 프론트가 보낸 값은 안 믿고, txHash로 영수증을 떼서
  로그에 적힌 user/optionId/amount를 읽어 DB에 적는다. "클라이언트를 믿지 말라"의 온체인 버전 ★.

## 4-4. ERC-20 — approve/transferFrom이 왜 있는 건가

ERC-20 = "토큰 컨트랙트가 구현해야 할 함수 목록" 표준 인터페이스 (transfer, balanceOf, approve, transferFrom, allowance...).
토큰 잔액의 실체 = **토큰 컨트랙트 안의 mapping(주소 => 잔액)** 한 줄. "코인이 지갑에 있다"는 말은 비유일 뿐.

**2단계 전송이 필요한 이유**: 내 토큰을 컨트랙트가 가져가게 하려면,
① 내가 토큰 컨트랙트에 `approve(예측컨트랙트주소, 한도)` 로 "쟤가 내 토큰 이만큼 가져가도 됨" 허가(서명 1)
② 예측 컨트랙트가 `transferFrom(나, 자기자신, 금액)` 으로 실제 회수 (placeBet 안에서, 서명 2)
→ 사용자가 참여할 때 **MetaMask 팝업이 두 번** 뜨는 이유. UX 상태머신(IDLE→APPROVAL→BET...)이 필요한 이유.

**decimals=18**: 소수점이 없으니 1토큰 = 10^18 최소단위(wei 방식)로 저장.
- JS number는 2^53까지만 정확 → **화면 표시 직전까지 bigint/문자열 유지** (`ethers.parseUnits("100", 18)` / `formatUnits`).
- 백엔드 DB도 raw 값은 NUMERIC/문자열로 (명세의 amountRaw가 이것).

## 4-6. ethers.js — 세 가지 객체만 알면 됨

| 객체 | 역할 | 만드는 곳 |
|---|---|---|
| **Provider** | 읽기 전용 연결 (잔액·영수증·view 호출) | 백엔드: `new JsonRpcProvider(RPC_URL)` / 프론트: `new BrowserProvider(window.ethereum)` |
| **Signer** | 서명 능력 있는 계정 | 프론트: `provider.getSigner()` → MetaMask 팝업 / (백엔드에 사용자 Signer를 두면 안 되는 이유 = 개인키 대행) |
| **Contract** | 주소+ABI를 함수 객체로 래핑 | `new Contract(addr, abi, providerOrSigner)` → `contract.placeBet(0, amt)` 처럼 호출 |

백엔드 영수증 검증의 뼈대 (우리 과제의 핵심 패턴):
```js
const receipt = await provider.getTransactionReceipt(txHash);
if (!receipt || receipt.status !== 1) throw ...;            // 존재·성공 확인
if (receipt.to !== FACTORY_ADDR) throw ...;                 // 대상 컨트랙트 확인
const log = iface.parseLog(receipt.logs.find(...));         // 이벤트 로그 파싱
// log.args의 온체인 값과 요청 바디를 대조한 뒤에만 DB 저장
```

## 4-7. MetaMask

- 브라우저 확장 지갑. 개인키를 브라우저 안에 암호화 보관, 서명 요청마다 팝업으로 사용자 승인.
- 페이지에 `window.ethereum` 객체를 주입 → ethers의 BrowserProvider가 이걸 감쌈.
- 개발 시 체크 3종: 설치 여부 / 계정 연결(`eth_requestAccounts`) / **네트워크 일치(chainId 31221)**.
- 사용자가 서명 거절하면 error code **4001** — 오류가 아니라 정상 시나리오로 처리(친절한 메시지).

# 5. 우리 프로젝트에 대입 — Sub PJT 1→3 지도

| 단계 | 배우는 것 | 위 노트의 어디 |
|---|---|---|
| Sub PJT 1 | TestToken(ERC-20), 단일 PredictionEvent, Hardhat 테스트 | §4-2, 4-4, 4-5 |
| Sub PJT 2 | Factory 패턴(이벤트마다 new로 컨트랙트 생성), 영수증 검증 API, 관리자 서명 화면 | §2-4, 4-3, 4-6 |
| Sub PJT 3 | 참여(approve→placeBet), 결과 확정·정산, 온체인-DB 정합성·복구, E2E | 전부 종합 |

**백엔드 개발자 관점에서 진짜 새로운 것 3가지:**
1. **진실의 원본이 내 DB가 아니다** — 서버는 검증자·캐시 관리자 역할로 물러남
2. **쓰기가 비동기이고 실패가 다층적** — 서명 거절/가스/revert/RPC 다운/API 실패가 다 다른 실패 ★(회로차단기·타임아웃 경험 직결)
3. **롤백 불가** — 온체인 성공 후 DB 실패 시, 온체인을 되돌리는 게 아니라 DB를 따라잡게 복구 (멱등 키 = txHash) ★(QoS1 중복·멱등 설계와 동일 문제)

# 6. 용어 사전 (빠른 참조)

| 용어 | 뜻 |
|---|---|
| 노드 | 체인 사본을 유지하고 트랜잭션을 실행·검증하는 서버 |
| RPC | 노드에 JSON-RPC로 말 거는 통로 (`https://rpc.ssafy-blockchain.com`) |
| chainId | 네트워크 식별 번호 (SSAFY=31221). 서명에 포함돼 다른 체인 재사용 방지 |
| mempool | 블록에 담기기 전 트랜잭션 대기줄 |
| finality | 블록이 "확정되어 되돌릴 수 없음" 상태가 되는 것 |
| wei | ETH의 최소 단위 (1 ETH = 10^18 wei). 토큰 raw 값도 같은 방식 |
| ABI | 컨트랙트 함수·이벤트 명세 JSON. 외부 호출의 인터페이스 문서 |
| revert | 실행 실패 + 전체 상태 롤백 |
| custom error | `error Foo();` + `revert Foo()` — require 문자열보다 싸고 구조적 |
| indexed | 이벤트 파라미터를 검색 가능하게 만드는 키워드 (최대 3개) |
| reentrancy | 외부 호출이 나를 되호출해 상태 꼬임을 노리는 공격. CEI 순서·ReentrancyGuard로 방어 |
| Ownable / onlyOwner | OpenZeppelin의 소유자 권한 패턴 |
| Factory 패턴 | 컨트랙트가 `new`로 다른 컨트랙트를 찍어내는 구조 (이벤트 1개 = 컨트랙트 1개) |
| EIP-1167 | 배포 가스를 아끼는 최소 프록시(클론) 표준 — 심화 언급용 |
| 오라클 | 체인 밖 현실 데이터(경기 결과 등)를 체인 안으로 넣어주는 존재. 체인은 스스로 바깥을 볼 수 없음 |
| 테스트넷 | 가치 없는 코인으로 도는 연습용 퍼블릭 체인 (Sepolia 등) |
| 논스(nonce) | 계정별 tx 일련번호. 순서 보장·재사용 방지 |
| 가스리스 | 가스비 0인 사설 체인 설정. 단, 가스 "한도"는 여전히 존재 |
